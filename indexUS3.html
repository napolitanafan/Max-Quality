Técnicas de aseguramiento de la calidad

Cómo se organizan las pruebas de software: en qué nivel del sistema se aplican y qué tanto conocimiento del código requieren.

Niveles de prueba

A medida que se sube de nivel, las pruebas cubren más del sistema pero se vuelven más lentas y costosas de mantener — por eso conviene tener muchas pruebas unitarias en la base y pocas de sistema en la cima.

Unitarias

Verifican una función o método de forma aislada, normalmente con datos simulados (mocks). Son numerosas, rápidas de ejecutar y baratas de mantener.

Integración

Verifican que dos o más módulos se comuniquen correctamente entre sí: llamadas a APIs, acceso a base de datos, servicios externos.

Sistema

Validan el sistema completo frente a los requisitos funcionales, simulando el uso real de principio a fin.

Tipos de prueba según el conocimiento del código

Más allá del nivel, cada prueba se diseña con un grado distinto de visibilidad sobre la implementación interna.

Caja Negra

Black Box Testing

Evalúa la funcionalidad sin conocer el código interno: se comparan las salidas obtenidas contra las salidas esperadas según la especificación, a partir de las entradas.

  • Partición de equivalencia entradas
  • Análisis de valores límite entradas
  • Tablas de decisión reglas

Caja Blanca

White Box Testing

Requiere conocer la estructura interna del código: los casos de prueba se diseñan para recorrer líneas, ramas y condiciones específicas del programa.

  • Cobertura de sentencias código
  • Cobertura de ramas código
  • Análisis de camino básico código
